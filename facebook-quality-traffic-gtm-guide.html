למה מעורבות באתר חשובה לקמפייני פייסבוק

כשמריצים קמפיין תנועה (Traffic) ב-Meta Ads Manager, יש כמה אפשרויות אופטימיזציה. בחירה ב-Link Clicks נותנת כמות — כל קליק נספר, גם אם המשתמש עזב לפני שהדף בכלל נטען. בחירה ב-Landing Page Views כבר מכוונת לאיכות: האלגוריתם מחפש אנשים שסביר שילחצו ויחכו שהדף ייטען.

אבל יש מגבלה קריטית: גם אופטימיזציה ל-Landing Page Views לא מודדת מעורבות אמיתית באתר כאות לאלגוריתם. התוצאה המוכרת — הרבה תנועה עם Average Session Duration נמוך: אנשים שסוגרים את הדף אחרי שנייה-שתיים, ומקבלים אותו משקל כמו גולש שקרא באמת. כמות בלי איכות.

✅ הפתרון בקצרה
משלבים שני טריגרים ב-GTM — Timer (זמן על הדף) + Scroll Depth (עומק גלילה) — לתוך Trigger Group אחד. הקבוצה יורה אירוע מותאם (Engaged Visit) ל-Meta, וזה הופך ל-Custom Conversion שאפשר לעשות עליו אופטימיזציה. כך אתה מלמד את מטא להביא רק ביקורים איכותיים.
📋 דרישה מקדימה
Google Tag Manager מותקן ופעיל באתר. אם ה-GTM עוד לא מחובר — צריך להשלים את זה קודם (הזרקת ה-container ל-<head> וה-<body>).

מתי להשתמש בזה — ומתי לא

לפני שמשקיעים בהטמעה: זו לא שיטה גורפת, אלא כלי לסיטואציות מסוימות. הפרוקסי "ביקור איכותי" מודד מעורבות — לא כוונת קנייה. בדוק אם זה מתאים למצב שלך.

✅ מתי כן — זה מתאים

  • קהל קר / טופ-פאנל (פרוספקטינג) שבו המרות אמת עדיין דלילות מדי לאופטימיזציה.
  • חשבון בנפח נמוך שלא מגיע ל-~50 המרות אמת בשבוע כדי לצאת מהלמידה.
  • קמפיין תוכן / טראפיק שמטרתו קריאה אמיתית (בלוג, מגזין, מאמר, PR).
  • כאות-גשר זמני — עד שנצבר מספיק דאטה של רכישה/ליד לעבור אליו.
  • כשהדף כבר טוב וה-Session Duration הנמוך נובע מטרגוט, לא מהדף.

⛔ מתי לא — עדיף להימנע

  • יש לך מספיק המרות אמת (רכישה/ליד) — אז עשה אופטימיזציה עליהן ישירות.
  • המטרה היא מכירות / ROAS — פרוקסי מעורבות עלול למצוא "גלגלנים", לא קונים.
  • ה-Session הנמוך הוא בעצם בעיית דף נחיתה / הצעה — אות טוב לא יתקן דף גרוע.
  • אתה מסתמך על View Content נקי בקמפיינים אחרים (המיפוי מזהם אותו).
  • אין לך CAPI — אירוע browser-side בלבד יאבד נתח גדול מהאותות.

חלק א׳ · הגדרת הטריגרים ב-Google Tag Manager

1

יצירת טריגר Scroll Depth (עומק גלילה)

GTM · TRIGGER

הטריגר הזה מזהה גולשים שגללו לפחות 50% מהדף — סימן שהם באמת קוראים ולא רק "נחתו ועפו".

  1. ב-GTM, עבור ל-Triggers ולחץ New.
  2. בחר Scroll Depth (תחת קטגוריית User Engagement).
  3. סמן Vertical Scroll Depths ← Percentages, והזן: 10, 25, 50, 75, 100
  4. בשדה This trigger fires on בחר Some Pages.
  5. הגדר את התנאי: Scroll Depth Threshold ← greater than or equal to ← 50
  6. תן שם: 50% Scroll Depth ולחץ Save.
2

יצירת טריגר Timer (זמן שהייה)

GTM · TRIGGER

הטריגר הזה מזהה גולשים ששהו על הדף זמן מינימלי. בדוגמה — 30 שניות, אבל כדאי להתאים לפי הדאטה של האתר שלך (זמן ממוצע שבו גולש מתעניין קורא).

  1. לחץ New ליצירת טריגר.
  2. בחר Timer (תחת קטגוריית Other).
  3. Interval — הזמן במילישניות. 30 שניות = 30000 (התאם לפי הדאטה שלך).
  4. Limit ← 1 (הטריגר יורה פעם אחת לכל היותר).
  5. תנאי: Page Path ← contains ← / (כדי שיפעל בכל דף באתר).
  6. בחר This trigger fires on ← All Timers.
  7. תן שם: 30+ Seconds on Page ולחץ Save.
💡 טיפ להתאמה אישית
אל תעתיק את 30 השניות באופן עיוור. פתח את הדאטה שלך (GA4 → Engagement) ובדוק כמה זמן גולש מתעניין באמת מבלה בדף. מספר גבוה מדי = מעט מדי אירועים לאלגוריתם ללמוד מהם; נמוך מדי = חוזרים לבעיית האיכות.
3

יצירת Trigger Group — איחוד שני התנאים

GTM · TRIGGER

עכשיו מאחדים את שני הטריגרים לקבוצה אחת. האירוע ייורה רק כששני התנאים מתקיימים יחד: 30+ שניות וגם 50%+ גלילה. זה הלב של "ביקור איכותי".

  1. לחץ New ליצירת טריגר.
  2. בחר Trigger Group (תחת קטגוריית Other).
  3. לחץ על תיבת Choose a Trigger ובחר 30+ Seconds on Page.
  4. לחץ על כפתור ה-+ הכחול ובחר 50% Scroll Depth.
  5. הגדר את התנאי ל-All Conditions (כל התנאים חייבים להתקיים).
  6. תן שם: 30+ Seconds / 50% Scroll ולחץ Save.

חלק ב׳ · חיבור Meta Pixel והזרקת האירוע

4

התקנת Meta Pixel דרך GTM

META · PIXEL

אם הפיקסל עוד לא מותקן — מתקינים אותו כתג Custom HTML שפועל בכל דף. (אם הפיקסל כבר קיים באתר, אפשר לדלג לשלב 5.)

  1. פתח את Events Manager ב-Meta (בטאב דפדפן חדש).
  2. לחץ Add Events ← From a New Website.
  3. בחלון שנפתח לחץ Install Code Manually.
  4. לחץ Copy Code להעתקת קוד הפיקסל.
  5. חזור ל-GTM ← Tags ← New.
  6. לחץ על תיבת Tag Configuration ובחר Custom HTML.
  7. הדבק את קוד הפיקסל בתיבת ה-HTML.
  8. לחץ Triggering ← בחר All Pages.
  9. תן שם: Meta Pixel ולחץ Save.

5

יצירת תג האירוע — "Engaged Visit"

META · CUSTOM EVENT

זה התג שמחבר הכל: תג Custom HTML שני, שיורה אירוע פייסבוק מותאם — אבל רק כשקבוצת הטריגרים מהשלב הקודם נדלקת.

  1. ממסך Tags לחץ New.
  2. לחץ Tag Configuration ← בחר Custom HTML.
  3. הזן את קוד המעקב הבא:
<script>
  fbq('trackCustom', 'Engaged Visit');
</script>
  1. לחץ Triggering ← בחר את קבוצת הטריגרים 30+ Seconds / 50% Scroll.
  2. תן שם לתג: Engaged Visit — שם זה יהפוך לשם האירוע ב-Events Manager.
  3. לחץ Save.
  4. לחץ על כפתור Submit הכחול.
  5. במסך Publish and Create Version הזן שם גרסה: Quality Visit tags + triggers.
  6. לחץ Publish.
💡 הערה על שם האירוע
המאמר משתמש ב-'Engaged Visit' עם רווח — וזה עובד עם trackCustom. עם זאת, best-practice היום הוא להימנע מרווחים ולהשתמש ב-EngagedVisit או engaged_visit, כדי למנוע בעיות התאמה בדוחות ובכלים אוטומטיים. רק שמור על עקביות — אותו שם בדיוק לאורך כל הדרך.
6

אימות ההטמעה — Test Events

META · QA

לפני שבונים קמפיין — מוודאים שהאירוע באמת נורה. בלי האימות הזה אתה עלול לבנות אופטימיזציה על אירוע שלא קיים.

  1. ב-Meta Events Manager פתח את לשונית Test Events.
  2. פתח את האתר שלך בטאב דפדפן חדש.
  3. גלול לפחות עד חצי הדף (50%+).
  4. הישאר בדף לפחות 30 שניות (או הזמן שהגדרת).
  5. חזור ל-Test Events — אחרי ~30 שניות האירוע Engaged Visit אמור להופיע ברשימה.
🎉 מזל טוב
אם האירוע הופיע — תצורת ה-GTM עובדת. עכשיו נשאר להפוך אותו ל-Custom Conversion ולחבר לקמפיין.

חלק ג׳ · הגדרת Custom Conversion וקמפיין

7

יצירת Custom Conversion + הוספה ל-AEM

META · CONVERSION

כדי שאפשר יהיה לעשות אופטימיזציה לאירוע בקמפיין, הופכים אותו ל-Custom Conversion, ומוסיפים אותו לרשימת ה-AEM (Aggregated Event Measurement) של הדומיין.

א. יצירת ה-Custom Conversion

  1. ב-Events Manager לחץ על Custom Conversions.
  2. לחץ על כפתור Create Custom Conversion הכחול.
  3. תן שם: Engaged Visit.
  4. הגדר Data Source ← הפיקסל (ה-Dataset) שלך.
  5. בחר Event ← Engaged Visit (עשוי לקחת עד 24 שעות עד שהאירוע יופיע ברשימה).
  6. בחר View Content כ-Standard Event לאופטימיזציה.
  7. הוסף לוכסן / בשדה ה-URL כדי שהמרה תיספר בכל דף באתר.
  8. לחץ Create.

ב. הוספה לרשימת ה-AEM (8 האירועים)

  1. פתח את Data Sources ← Overview.
  2. לחץ על Aggregated Event Measurements.
  3. לחץ Configure Web Events.
  4. לחץ Manage Events.
  5. הוסף את האירוע לרשימת 8 האירועים — מומלץ במיקום נמוך (Lowest Priority) כי זה מיקרו-אירוע.
  6. שמור את השינויים (עדכון עשוי לקחת עד 72 שעות).
🔄 עדכון 2026
שלב ה-AEM עדיין תקף ורלוונטי — נשארו 8 אירועי המרה מדורגים לדומיין מאומת. שני דגשים: (1) ודא שהדומיין שלך מאומת ב-Business Settings, אחרת לא תוכל להגדיר את האירועים; (2) זכור שכל שינוי ב-AEM עלול לאפס זמנית את הלמידה של קמפיינים פעילים ולקחת עד 72 שעות להיכנס לתוקף — תזמן בהתאם.
8

שימוש ב-Custom Conversion בקמפיין

META · CAMPAIGN

השלב האחרון — לבנות קמפיין שממקסם את הביקורים האיכותיים במסגרת התקציב.

  1. צור קמפיין חדש ב-Meta Ads Manager.
  2. בחר את האובייקטיב Conversions.
  3. ברמת ה-Ad Set, בחר את ה-Custom Conversion שיצרת (Engaged Visit) כאירוע האופטימיזציה.
🔄 עדכון 2026 — זה השלב שהכי השתנה
אובייקטיב "Conversions" כבר לא קיים. במבנה ODAX החדש (6 אובייקטים) הוא הוחלף ב-Sales. הזרימה הנכונה היום:
קמפיין חדש ← אובייקטיב Sales ← ברמת ה-Ad Set: Conversion Location = Website ← Performance Goal = Maximize number of conversions ← Conversion Event = Engaged Visit
התוצאה זהה למה שהמאמר מתאר — הקמפיין מתמקד במקסום ביקורים איכותיים — רק דרך התפריט המעודכן.

שורה תחתונה

ביקורים איכותיים תמיד קודמים לכמות. זה לא על מקסום מספרים — זה על מקסום תוצאות. מיקרו-המרות (כמו "ביקור איכותי") מזיזות אותך מכמות לאיכות, ומייצרות יותר לידים ומכירות בטווח הארוך.

  • ליצור מודעה שמייצרת קליקים זה השלב הראשון — לשכנע את הגולש לקרוא ולפעול זה הקריטי.
  • מערכות ואלגוריתמים ממקסמים תוצאות רק כשמזינים אותם במספיק אותות איכותיים כדי למצוא את הקהל הנכון.
  • הכרת הקהל שלך ומה מניע אותו = המפתח לשימוש יעיל במערכות.
⚠️ מה לצפות: מעבר מאופטימיזציה ל-Traffic/Link Clicks לאופטימיזציה להמרות (ביקורים איכותיים) יקטין את מספר התוצאות ויעלה את העלות לתוצאה. זה תקין ומצופה — אתה מייצר עכשיו ביקורים איכותיים ומבטל את הבזבוז ששילמת עליו קודם. צמצום הבזבוז חוסך כסף בטווח הארוך ומאפשר להקצות תקציב ביעילות לצמיחה.

📝 ביקורת אובייקטיבית על המאמר

ציון 7/10
ביצוע מצוין ורעיון תקף — אבל מסגור אסטרטגי חסר ולא מגובה בדאטה. לא לשבח ולא לרסק, דעה אמיתית.
💪 מה עובד
  • אבחנה נכונה. תנועה מ-Link Clicks / LPV באמת נשפכת — כאב אמיתי של מפרסמים.
  • הרעיון תקף מכנית. מטא ממקסם את מה שמזינים לו; אות טוב מ"קליק" = מנוף אמיתי, לא טריק.
  • אות מורכב (AND). זמן וגם גלילה יחד מסננים רעש טוב יותר מכל תנאי לבד.
  • כנות. אומר במפורש שהעלות-לתוצאה תעלה — יושרה שרוב מדריכי ה"טאקטיקה" מדלגים עליה.
  • ניתן לשחזור. שלב-שלב עם צילומי מסך, בלי צורך במפתח.
⚠️ החולשות
  • פרוקסי שגוי. מודד מעורבות, לא כוונת קנייה — עלול ללמד את האלגוריתם לחפש קוראים, לא קונים.
  • טיימר = זמן-בטאב, לא תשומת לב. GA4 engaged sessions מדויק יותר (נעצר כשהטאב מוסתר).
  • אין תיחום. מוצג כ-best practice גורף, בלי לומר מתי זה עוזר ומתי מזיק.
  • מיפוי ל-View Content מזהם דאטה שקמפיינים אחרים מסתמכים עליה.
  • ספים שרירותיים. 50% גלילה תלוי-אורך-דף — לא אות אחיד בין עמודים.
  • אפס ראיות. טוען "יותר מכירות בטווח הארוך" בלי Case Study / holdout / before-after.
  • מטפל בסימפטום. Session נמוך הוא לרוב בעיית דף/הצעה — לא טרגוט.
  • האות הכי שביר. browser-side למיקרו-המרה = בדיוק מה שנפגע מ-iOS14 בלי CAPI.
שורה תחתונה: מדריך טאקטי טוב לרמת ביניים, מדויק טכנית וישר לגבי המחיר — אבל מוכר-יתר את עצמו אסטרטגית. השתמש בו לקהל קר / נפח נמוך כאות-גשר זמני, ועבור לאופטימיזציה על האירוע העסקי האמיתי (רכישה/ליד) ברגע שיש מספיק נפח. לא תחליף לאופטימיזציה על מכירה כשיש דאטה.
