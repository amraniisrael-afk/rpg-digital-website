מה זה טריגר Custom Event ב-GTM?

הבסיס שצריך להבין לפני שמתחילים

אירוע מותאם אישית (Custom Event) הוא טריגר ב-GTM שמופעל כאשר קוד האתר "דוחף" (Push) מידע לשכבת המידע (Data Layer). זה בניגוד לטריגרים מובנים כמו Page View או Click — שם GTM עושה את העבודה לבד.

כאן האתר הוא זה שיוזם ומגדיר מה נשלח. זה מאפשר שליטה מלאה על הנתונים: מה קרה, מתי, ועם אילו פרטים.

💡 מתי משתמשים בזה?

בכל מצב שבו הכלים המובנים של GTM "עיוורים" למה שקורה — למשל: טפסים מורכבים שנשלחים ללא רענון עמוד (SPA), רכישות בחנות אלקטרונית (purchase), הוספה לסל (add_to_cart), או כל פעולה שה-Dev שלך כבר עקב אחריה בקוד.

2

הכוח של "Some Custom Events" — סינון מותנה

ההבדל בין טריגר שמפעיל כל דבר לטריגר שמפעיל רק את מה שחשוב

⚠️ All Custom Events

ברירת המחדל

מפעיל את הטריגר בכל פעם שהאירוע קורה — בכל רכישה, בכל סכום. הפיקסל יקבל נתונים על כולם — קונה ב-30 ש"ח ולקוח VIP ב-3,000 ש"ח יאוחדו לאותו קהל.

✅ Some Custom Events

עם פילטר חכם

מאפשר להציב תנאי נוסף. הטריגר יופעל רק אם האירוע קרה וגם התנאי הנוסף מתקיים. כמו מאבטח שמכניס רק מי שעומד בקריטריונים.

🎯

האנלוגיה: All Custom Events = מאבטח שמכניס כל מי שמגיע. Some Custom Events = מאבטח שבודק גם את הסיסמה וגם שלובש חולצה לבנה — רק מי שעומד בשניהם נכנס.

הגדרת הטריגר — סינון רכישות מעל 500 ש"ח

5 שלבים מדויקים ב-GTM

1

יצירת טריגר חדש

ב-GTM נכנסים ל-Triggers → New ומגדירים את סוג הטריגר כ-Custom Event.

2

Event Name

בשדה שם האירוע כותבים בדיוק: purchase — חייב להתאים לשם שהדאטאלייר דוחף. תלוי-רישיות!

3

בחירת "Some Custom Events"

תחת This trigger fires on, מסמנים Some Custom Events (לא All). זה פותח שורת תנאי.

4

הגדרת התנאי

בשדה השמאלי בוחרים את המשתנה: {{Ecommerce Price Value}}
באמצע בוחרים: greater than
בשדה הימני מקלידים: 500

5

שמירה וקישור לתג

שומרים את הטריגר ומקשרים אותו לתג פיקסל פייסבוק עם שם האירוע הייחודי (למשל PurchaseVIP).

⚠️

דגש קריטי: אם שדה הערך הימני נשאר ריק, המערכת תציג שגיאה באדום — "Invalid filter specified". חובה להזין ערך מספרי כדי שה-GTM ידע מול מה להשוות את המחיר.

4

בדיקה ואימות — איך יודעים שהכל עובד?

שני ערוצי בדיקה שמשלימים אחד את השני

ערוץ 1: GTM Preview Mode

נכנסים למצב תצוגה מקדימה ומבצעים רכישות טסט:

  • ✓
    רכישה מעל 500 ש"ח — התג חייב להופיע תחת Tags Fired. אם הוא לא שם — בדוק שם המשתנה ושם האירוע.
  • ✗
    רכישה של 50 ש"ח — התג חייב להישאר תחת Tags Not Fired. אם הוא ירה — יש בעיה בתנאי הסינון.
  • ✓
    רכישה של 501 ש"ח בדיוק — בדיקת גבול (edge case). Greater than ≠ Greater or equal. ודא שהלוגיקה תואמת את הציפייה.

ערוץ 2: Meta Events Manager

בלשונית Test Events, מזינים את כתובת האתר ומבצעים רכישה. תראו בזמן אמת שהפיקסל מקבל את האירוע הייחודי שהגדרת — שם האירוע, הערך, המטבע.

✅ סימן שעובד כמו שצריך

ב-Events Manager מופיע האירוע PurchaseVIP עם ה-value הנכון — ולא האירוע הסטנדרטי Purchase הרגיל. שתי האירועים יכולים לרוץ במקביל — זה לא בעיה.

הקטיף השיווקי — 3 שימושים לקהל ה-VIP

מהרגע שהתג מפורסם ומקבל נתונים, הכסף האמיתי מתחיל

נכנסים ל-Meta Audiences → Create Audience → Custom Audience → Website. בחרו את האירוע הייחודי שיצרתם.

🎯

Lookalike איכותי

ה-AI של Meta מחפש אנשים שדומים רק לקונים הגדולים שלך — לא לכל מי שקנה משהו. המקור באיכות גבוהה = ה-LAL באיכות גבוהה.

💎

רימרקטינג VIP

קמפיין ממוקד עם מוצרי פרימיום, הטבות בלעדיות או שירות מועדף — רק לאנשים שהוכיחו נכונות לשלם.

🚫

החרגה חכמה

מחריגים את ה-VIP מקמפיינים של מוצרים זולים — לא מבזבזים תקציב פרסום על מי שיכול לשלם הרבה יותר.

🔍

מתי משתמשים בגישה הזו?

4 תרחישים עסקיים שמצדיקים קהל VIP נפרד

🛍️

איקומרס עם AOV גבוה

חנות עם מוצרים ב-50–3,000 ש"ח — ה-AOV האמיתי שלך נחבא מאחורי ממוצע. הפרד את הקונים הגדולים.

📦

מוצרי פרימיום vs. Entry-level

יש לך מוצר במחיר כניסה וגרסה יקרה יותר — הקהל שקנה יקר הוא הטרגט הכי טוב לגרסה הפרימיום.

🎁

מועדון לקוחות / VIP Club

רוצה לבנות תוכנית נאמנות? הקהל הזה הוא רשימת ה-VIP שלך — פרסם להם הזמנות אישיות.

📊

אופטימיזציית ROAS אמיתית

אם האלגוריתם לומד מכל הרכישות — הוא ממוצע. אם הוא לומד רק מהטובות ביותר — הוא חד.

🏆

הסיכום בשורה אחת

GTM Custom Events עם Some Custom Events + סינון על מחיר = הזנת הפיקסל רק בנתוני הזהב שלך. קהל VIP ממיר טוב יותר, Lookalike יותר חד, ותקציב שמגיע לאנשים הנכונים.
