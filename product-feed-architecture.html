1
מהו פיד מוצרים?

פיד מוצרים הוא קובץ מובנה שמכיל את כל המידע על המוצרים שלך — מחיר, תמונה, כותרת, זמינות — ומועבר לפלטפורמות פרסום כדי שיוכלו להציג מודעות דינמיות. הפלטפורמה לא נכנסת לאתר שלך בזמן אמת — היא עובדת מהפיד בלבד. אם הפיד שגוי, המודעות שגויות.

ברגע שמשתמש מחפש "נעלי ריצה שחורות" בגוגל, גוגל לא "סורקת" את האתר שלך כדי למצוא מוצרים — היא מחפשת בפיד שהעלית מראש ל-Merchant Center. לכן הפיד הוא הבסיס לכל מה שקורה בקמפיינים של Shopping ו-DPA.

האתר שלך ──► פיד (XML/CSV/JSON) ──► Google Merchant Center ──► Google Shopping ──► Meta Catalog ──► DPA Ads ──► TikTok Catalog ──► TikTok Shopping ──► Criteo / Pinterest ──► Retargeting
⚡
חשוב להבין: שיפור בפיד (כותרות, תמונות, Custom Labels) משפיע ישירות על CTR, ROAS ועלות לקליק — לפעמים יותר מכל שינוי בהגדרות הקמפיין עצמו.
2
שדות חובה ושדות רצויים

כל מוצר בפיד הוא שורה נתונים עם שדות שמגדירים מה הוא, כמה הוא עולה ואיפה אפשר לקנות אותו. גוגל מחלקת אותם ל-חובה (ללא זה הפיד נדחה) ו-רצויים (שיפור ביצועים).

שדות חובה — בלעדיהם הפיד נדחה

שדה מה זה ולמה זה נדרש דוגמה
id מזהה ייחודי. גוגל ו-Meta עוקבות אחרי כל מוצר לפי ID זה — אם תשנה אותו, המוצר "נולד מחדש" ומאבד את ההיסטוריה שלו SKU-1234
title שם המוצר כפי שיופיע במודעה. אחד השדות הכי קריטיים ל-CTR — גוגל ממתחת מילות מפתח בתוצאות Shopping נעלי ריצה Nike Air Max 270 שחור 42
description תיאור מלא. לא תמיד מוצג למשתמש, אבל גוגל קוראת אותו להבנת הרלוונטיות של המוצר נעליים עם כרית אוויר...
link URL לדף המוצר — גוגל מבקרת בדף לאמת שהמחיר והזמינות תואמים לפיד https://site.co.il/product/1234
image_link URL לתמונה הראשית. זה מה שרואים תחילה — לוקח ריבועי שטח גדול ב-Shopping ומשפיע ישירות על CTR https://cdn.site.co.il/1234.jpg
price חייב להיות זהה למחיר בדף. גוגל בודקת — אי-התאמה = דחיית המוצר. פורמט: מספר + מרווח + מטבע 299.00 ILS
availability ערכים מותרים בלבד: in stock / out of stock / preorder. לא "במלאי" בעברית in stock
brand שם המותג — עוזר לגוגל לסווג ולהתאים לחיפושים ברמת מותג Nike
gtin ברקוד בינלאומי (EAN/UPC/ISBN). עוזר לגוגל לזהות את המוצר בוודאות ולהתאים לחיפושים מדויקים. ללא GTIN — המוצר מקבל ציון נמוך יותר 5901234123457
google_product_category קטגוריה מרשימת גוגל (6,000+ אפשרויות). ככל שמדויקת יותר — Impressions ממוקדים יותר. ראה סקשיין 5 Apparel & Accessories > Shoes

שדות רצויים — משפרים ביצועים משמעותית

שדות אלו לא חובה, אבל כל שדה שנוסיף נותן לגוגל יותר מידע — והיא יכולה להציג את המוצר למשתמשים יותר רלוונטיים.

xml — שדות מומלצים עם הסבר 
<!-- תמונה נוספת — גוגל תבחר אוטומטית מה להציג לפי placement -->
<additional_image_link>https://cdn.site.co.il/1234-side.jpg</additional_image_link>

<!-- מחיר מבצע — מוצג עם קו חוצה על המחיר המקורי: 199₪ ~~299₪~~ -->
<sale_price>199.00 ILS</sale_price>

<!-- תאריכי המבצע — תחילה/סוף בפורמט ISO 8601 עם אזור זמן -->
<sale_price_effective_date>2026-06-01T00:00:00+03:00/2026-06-30T23:59:59+03:00</sale_price_effective_date>

<!-- מצב: new / used / refurbished — ייתכן מסנן בחיפוש -->
<condition>new</condition>

<!-- צבע, מידה, מין, גיל — משפרים התאמה לחיפושים כמו "נעליים כחולות 42" -->
<color>שחור</color>
<size>42</size>
<age_group>adult</age_group>
<gender>male</gender>

<!-- Custom Labels — שדות שאתה ממלא כרצונך, לשימוש פנימי בקמפיינים (ראה סקשיין 6) -->
<custom_label_0>high_margin</custom_label_0>
<custom_label_1>bestseller</custom_label_1>

פורמטים — XML / JSON / CSV

הנתונים מועברים לפלטפורמות בפורמטים שונים. הבחירה תלויה בפלטפורמה ובגודל הפיד.

XML
Google Shopping

הפורמט הרשמי של גוגל. מבוסס RSS 2.0 עם namespace מיוחד (g:). מתאים לפידים גדולים ומורכבים.

JSON
Meta / TikTok / Criteo

פורמט קל לעיבוד בצד ה-API. Meta מעדיפה אותו כי המערכות שלה "מדברות" JSON באופן טבעי.

CSV
כל הפלטפורמות

הפשוט ביותר — פתיח ב-Excel. מתאים לחנויות קטנות שמעדכנות ידנית. מגביל בנתונים מורכבים.

XML — הפורמט הנפוץ ביותר ל-Google

למה XML נראה ככה?
השורה <?xml version="1.0" encoding="UTF-8"?> אומרת לתוכנה שזה מסמך XML. ה-xmlns:g הוא "מרחב שמות" — כל שדה שמתחיל ב-g: הוא שדה גוגל ספציפי. ה-<rss> הוא מעטפת, ה-<channel> הוא הקטלוג, וכל <item> הוא מוצר.
xml 
<!-- הצהרה על גרסה וקידוד תווים -->
<?xml version="1.0" encoding="UTF-8"?>

<!-- rss = מבנה RSS 2.0 | xmlns:g = namespace של גוגל -->
<rss version="2.0" xmlns:g="http://base.google.com/ns/1.0">
  <channel>  <!-- הקטלוג כולו -->

    <item>  <!-- מוצר אחד -->
      <g:id>SKU-1234</g:id>
      <g:title>נעלי ריצה Nike Air Max 270 - שחור 42</g:title>
      <g:price>599.00 ILS</g:price>         <!-- חובה: מספר + רווח + מטבע -->
      <g:sale_price>399.00 ILS</g:sale_price> <!-- אופציונלי: מחיר מבצע -->
      <g:availability>in stock</g:availability>
      <g:brand>Nike</g:brand>
      <g:gtin>0885178578574</g:gtin>       <!-- ברקוד EAN/UPC -->
      <g:color>שחור</g:color>
      <g:size>42</g:size>
      <g:custom_label_0>sale</g:custom_label_0>
    </item>

    <!-- מוצר נוסף מיד אחריו... -->

  </channel>
</rss>

JSON — נפוץ ב-Meta ו-TikTok

למה JSON ב-Meta ולא XML?
Meta בנתה את מערכות ה-API שלה סביב JSON — זה הפורמט שהשרתים שלה "מדברים". ה-"data": [...] הוא מערך (רשימה) של מוצרים. כל מוצר הוא אובייקט עם מפתח-ערך, ה-keys זהים לשדות ב-XML אבל ללא הקידומת g:.
json 
{
  "data": [    // מערך של כל המוצרים
    {
      "id": "SKU-1234",
      "title": "נעלי ריצה Nike Air Max 270 - שחור 42",
      "availability": "in stock",
      "price": "599.00 ILS",
      "sale_price": "399.00 ILS",
      "link": "https://mystore.co.il/products/nike-air-max-270",
      "image_link": "https://cdn.mystore.co.il/images/nike-1234.jpg",
      "brand": "Nike",
      "custom_label_0": "high_margin"
    },
    {    // מוצר שני מיד אחרי
      "id": "SKU-1235",
      ...
    }
  ]
}

CSV — הכי פשוט, מתאים לחנויות קטנות

מה זה CSV ואיך זה עובד?
CSV = Comma Separated Values. שורה ראשונה = שמות העמודות (headers). כל שורה אחר כך = מוצר אחד. ערכים עם פסיקות בתוכם חייבים להיות בגרשיים — לכן "נעלי ריצה Nike..." בגרשיים. הכי קל לפתוח ולערוך ב-Excel.
csv 
# שורה 1 = headers (שמות השדות)
id,title,price,availability,brand,color,size,custom_label_0

# שורה 2 = מוצר ראשון
SKU-1234,"נעלי ריצה Nike Air Max 270 - שחור 42","599.00 ILS","in stock","Nike","שחור","42","sale"

# שורה 3 = מוצר שני
SKU-1235,"נעלי ריצה Nike Air Max 270 - לבן 41","599.00 ILS","in stock","Nike","לבן","41","regular"

ארכיטקטורה — בסיסית ומתקדמת

ארכיטקטורה בסיסית — חנות קטנה (עד 5,000 מוצרים)

ארבעה שלבים. כל שלב מעביר את הנתונים לשלב הבא:

מסד נתונים
שם יושבים המוצרים: שמות, מחירים, מלאי, תמונות
──►
סקריפט PHP/Python
קורא מה-DB, ממיר לפורמט XML תקני, מייצר את הקובץ
──►
feed.xml
קובץ סטטי בשרת — גוגל מורידה אותו בתזמון קבוע
──►
Merchant Center
מקבל, מאמת ומפיץ לקמפיינים
מה הסקריפט PHP/Python עושה בדיוק?
הסקריפט הוא ה"גשר" בין מסד הנתונים לבין הפורמט שגוגל מצפה לו. הוא:

1. קורא מה-DB — שולף את כל המוצרים עם מחיר, זמינות, תמונה, קטגוריה
2. ממיר — מחיר "299" הופך ל-"299.00 ILS", זמינות "1" הופכת ל-"in stock"
3. מחשב — מרווח רווח, Custom Labels, האם המוצר במבצע
4. כותב — מייצר קובץ XML תקני ושומר אותו בשרת

הסקריפט רץ בתזמון (Cron Job) — למשל כל שעה — ומחדש את הקובץ. גוגל מורידה את הקובץ אוטומטית לפי לו"ז שהגדרת ב-Merchant Center.

דוגמה: סקריפט בסיסי שמייצר פיד XML

python — feed generator 
import xml.etree.ElementTree as ET
import mysql.connector

def generate_feed():
    # שלב 1: שליפת מוצרים ממסד הנתונים
    db = mysql.connector.connect(host="localhost", database="shop")
    cursor = db.cursor(dictionary=True)
    cursor.execute("""
        SELECT id, name, price, cost_price, stock, image_url,
               category, brand, gtin, color, size
        FROM products
        WHERE active = 1
    """)
    products = cursor.fetchall()

    # שלב 2: בניית מבנה XML
    rss = ET.Element("rss", version="2.0")
    rss.set("xmlns:g", "http://base.google.com/ns/1.0")
    channel = ET.SubElement(rss, "channel")

    for product in products:
        item = ET.SubElement(channel, "item")

        # שלב 3: המרת נתוני DB לפורמט של גוגל
        ET.SubElement(item, "g:id").text = str(product["id"])
        ET.SubElement(item, "g:title").text = product["name"]

        # המרת מספר לפורמט "299.00 ILS" שגוגל מצפה לו
        ET.SubElement(item, "g:price").text = f'{product["price"]:.2f} ILS'

        # המרת 1/0 מה-DB לטקסט שגוגל מבינה
        availability = "in stock" if product["stock"] > 0 else "out of stock"
        ET.SubElement(item, "g:availability").text = availability

        # שלב 4: חישוב Custom Label לפי מרווח רווח
        margin = (product["price"] - product["cost_price"]) / product["price"]
        label = "high_margin" if margin >= 0.4 else "low_margin"
        ET.SubElement(item, "g:custom_label_0").text = label

    # שלב 5: שמירת הקובץ בשרת כדי שגוגל תוכל להוריד אותו
    tree = ET.ElementTree(rss)
    tree.write("/var/www/public/feed.xml", encoding="UTF-8", xml_declaration=True)
    print(f"פיד נוצר: {len(products)} מוצרים")

generate_feed()

ארכיטקטורה מתקדמת — חנות גדולה / אגרסיבית

כשיש עשרות אלפי מוצרים ומחירים משתנים תכופות, צריך שכבות נוספות:

┌──────────────────────────────────────────────────────┐ │ מקורות נתונים │ │ ERP (מחירים, עלויות) + מחסן (מלאי) + Analytics │ └─────────────────────┬────────────────────────────────┘ │ נתונים גולמיים, לא מוכנים ▼ ┌──────────────────────────────────────────────────────┐ │ Feed Processing Layer (5 שלבים) │ │ 1. Extraction — שליפה ממקורות שונים │ │ 2. Normalization — אחידות פורמט │ │ 3. Enrichment — הוספת נתונים חסרים │ │ 4. Validation — בדיקת שגיאות לפני שליחה │ │ 5. Segmentation — פיצול לפי Custom Labels │ └─────────────────────┬────────────────────────────────┘ │ פיד מוכן ומאומת ▼ ┌──────────────────────────────────────────────────────┐ │ Feed Distribution │ │ Google Merchant Center (XML) │ │ Meta Business Manager (JSON) │ │ TikTok Catalog (CSV) / Criteo / Pinterest │ └──────────────────────────────────────────────────────┘

מה עושה כל שלב ב-Feed Processing Layer?

  • 1
    Extraction — שליפה שולף נתונים ממקורות שונים: מחירים מה-ERP, מלאי ממערכת המחסן, ביצועים מ-GA4. הבעיה: כל מערכת "מדברת" פורמט שונה.
  • 2
    Normalization — אחידות ממיר הכל לפורמט אחד. דוגמה: ERP שומר מחיר כ-29900 (אגורות), הפיד צריך 299.00 ILS. קטגוריה מה-DB: "SHOES_MEN" → Google Taxonomy: "Apparel & Accessories > Shoes".
  • 3
    Enrichment — העשרה מוסיף נתונים שלא קיימים במסד הנתונים. למשל: חישוב Custom Labels לפי מרווח (נדרש מ-2 שדות), שליפת GTIN מ-API חיצוני, הוספת תמונת lifestyle לפי קטגוריה.
  • 4
    Validation — אימות בודק שהפיד "בריא" לפני השליחה: האם כל מוצר יש לו כותרת? האם המחיר בפורמט נכון? האם יש מוצרים עם GTIN לא תקין? כל בעיה שנתפסת כאן לא הופכת לדחייה ב-Merchant Center.
  • 5
    Segmentation — פיצול מחלק את המוצרים לקבוצות לפי Custom Labels (מרווח גבוה / נמוך / מבצע / מלאי נמוך). כך ניתן להפעיל אסטרטגיות בידינג שונות לכל קבוצה בקמפיין.
5
טקסונומיה וקטגוריות גוגל

גוגל מתחזקת רשימה של ~6,000 קטגוריות בהיררכיה. ככל שהקטגוריה ספציפית יותר, גוגל יודעת בדיוק מה אתה מוכר ומציגה את המוצר למשתמשים עם כוונת קנייה ספציפית יותר — וזה שווה CTR גבוה יותר.

✗
רע: google_product_category = "בגדים"
גוגל לא יודעת אם זה גרביים, מעיל, או תחתונים. מציגה למגוון רחב ולא ממוקד.
✓
טוב: Apparel & Accessories > Clothing > Shirts & Tops > T-Shirts
גוגל יודעת שזה חולצת טי — מציגה למי שחיפש "חולצת טי" ספציפית, לא "בגד" כללי.
איך זה משפיע על הביצועים?
גוגל משתמשת בקטגוריה גם לקביעת ה-benchmark — כמה המתחרים בתחום שלך משלמים. קטגוריה כללית = תחרות עם כולם. קטגוריה ספציפית = תחרות רק עם מתחרים ישירים שלך. בנוסף, Shopping ads מציגות לפי match בין החיפוש לקטגוריה.

6
Custom Labels — הכלי הסודי לפיצול קמפיינים

Custom Labels הם 5 שדות חופשיים (custom_label_0 עד custom_label_4) שאתה ממלא כרצונך. הפלטפורמה לא עושה איתם כלום בעצמה — הם עבורך, כדי לפצל קמפיינים לפי כל לוגיקה עסקית שתבחר.

למה זה כל כך חשוב?
בלי Custom Labels יש לך קמפיין אחד עם Target ROAS אחד לכל המוצרים. עם Custom Labels אתה יכול להפעיל Target ROAS שונה לכל קבוצת מוצרים — מוצרים עם מרווח גבוה מקבלים תקציב גדול, מוצרים עם מרווח נמוך מקבלים מינימום. זו הסיבה שחנויות מתקדמות מכות מתחרים עם אותו תקציב.

python — מחושב אוטומטית בסקריפט הפיד 
def calculate_custom_labels(product: dict, sales_data: dict) -> dict:
    # ── Label 0: מרווח רווח ──────────────────────────────────────────
    # (מחיר מכירה - מחיר עלות) / מחיר מכירה = אחוז מרווח
    cost  = product.get("cost_price", 0)   # עלות: 150 ₪
    price = product.get("price", 0)       # מחיר: 300 ₪
    margin = (price - cost) / price if price > 0 else 0  # = 0.5 = 50%

    label_0 = ("high_margin"   if margin >= 0.4   # מרווח 40%+
          else "medium_margin" if margin >= 0.2   # מרווח 20-39%
          else "low_margin")               # מרווח מתחת ל-20%

    # ── Label 1: ביצועי מכירות (30 יום) ─────────────────────────────
    # sales_data הוא dict שמגיע מ-GA4/Analytics: {product_id: {units_30d: N}}
    units_sold = sales_data.get(product["id"], {}).get("units_30d", 0)

    label_1 = ("bestseller"  if units_sold >= 20  # 20+ יחידות = מנצח
          else "regular"    if units_sold >= 5   # 5-19 יחידות = סביר
          else "slow_mover")              # פחות מ-5 = עצלן

    # ── Label 3: מצב מלאי ────────────────────────────────────────────
    stock = product.get("stock_quantity", 0)

    label_3 = ("low_stock"  if stock <= 3              # 3 יחידות אחרונות — האט
          else "clearance" if product.get("on_sale")   # במבצע ממאגר — פנה
          else "plenty")                            # מלאי תקין

    return {
        "custom_label_0": label_0,
        "custom_label_1": label_1,
        "custom_label_3": label_3,
    }

Delta Feed — איך מזהים מה השתנה?

מה זה hashlib.md5 ולמה זה פתרון גאוני?
הבעיה: איך יודעים אם מוצר השתנה מהשעה הקודמת? לא רוצים להשוות שדה-שדה לכל 50,000 מוצרים.

הפתרון — hash: md5 הוא פונקציה שמייצרת "טביעת אצבע" ייחודית לכל קבוצת נתונים. הנתונים {"price": 299, "availability": "in stock"} יניבו תמיד אותו hash: a3f2b1.... אם המחיר השתנה ל-199 — ה-hash ישתנה לחלוטין: 7d9c4e....

כל שעה: מחשבים hash חדש ומשווים ל-hash הקודם. אם שונה → מוצר השתנה → שולחים אותו בלבד.
python — זיהוי שינויים יעיל 
import hashlib, json

def generate_delta_feed(current_products: list, prev_hashes: dict) -> list:
    """מחזיר רק את המוצרים שהשתנו מהעדכון הקודם"""
    changed = []

    for product in current_products:
        # השדות שאכפת לנו מהם — מחיר, מבצע, זמינות, מלאי
        key_fields = {
            "price":        product["price"],
            "sale_price":   product.get("sale_price"),
            "availability": product["availability"],
            "stock":        product.get("stock_quantity"),
        }
        # יצירת טביעת אצבע ייחודית לנתונים הנוכחיים
        current_hash = hashlib.md5(
            json.dumps(key_fields, sort_keys=True).encode()
        ).hexdigest()  # → "a3f2b1c4d8..." (32 תווים)

        pid = product["id"]
        # אם ה-hash שונה מהשמור — הנתונים השתנו
        if prev_hashes.get(pid) != current_hash:
            changed.append(product)        # הוסף לרשימת השינויים
            prev_hashes[pid] = current_hash  # שמור את ה-hash החדש

    print(f"{len(changed)} מוצרים השתנו מתוך {len(current_products)}")
    return changed  # → רק אלו שישלחו בפיד

Content API — עדכון בזמן אמת

כשהשינוי דחוף מכדי לחכות לסריקה הבאה, Content API של Google מאפשר לשלוח עדכון ישירות ל-Merchant Center — מוצר אחד בכמה שניות.

מה זה service_account.json?
כדי שהסקריפט שלך ידבר עם Merchant Center, גוגל צריכה לדעת שאתה מורשה. הפתרון: Service Account — "עובד ווירטואלי" שאתה יוצר ב-Google Cloud Console, מקצה לו הרשאות, ומוריד קובץ JSON עם "מפתח" מוצפן. הסקריפט מציג את הקובץ הזה לגוגל — וגוגל מאמינה שזה אתה.

איך מקבלים אותו? Google Cloud Console → IAM & Admin → Service Accounts → Create → Download JSON.
python — Content API, עדכון מוצר בודד בזמן אמת 
from google.oauth2 import service_account
from googleapiclient.discovery import build

def update_product_realtime(merchant_id: str, product_id: str, updates: dict):
    # אימות מול גוגל עם service_account.json (הקובץ שהורדת מ-Cloud Console)
    credentials = service_account.Credentials.from_service_account_file(
        "service_account.json",
        scopes=["https://www.googleapis.com/auth/content"]  # הרשאה ל-Merchant Content
    )
    service = build("content", "v2.1", credentials=credentials)

    # שליפת הנתונים הנוכחיים של המוצר מ-Merchant Center
    # product_id בפורמט: online:שפה:מדינה:מזהה
    product = service.products().get(
        merchantId=merchant_id,
        productId=f"online:he:IL:{product_id}"
    ).execute()

    # עדכון השדות הרלוונטיים בלבד (שאר השדות נשמרים)
    product.update(updates)

    # שמירה חזרה ל-Merchant Center — נכנסת לתוקף תוך דקות
    result = service.products().update(
        merchantId=merchant_id,
        productId=f"online:he:IL:{product_id}",
        body=product
    ).execute()
    return result

# ── שימוש: מוצר נגמר — עדכן מיד ──────────────────────────

        "availability": "out of stock",
        "price": {"value": "399.00", "currency": "ILS"}
    }

שגיאה 2: תמונות לא עומדות בדרישות

הסקריפט הבא סורק את כל התמונות בפיד ומדווח על בעיות — לפני ששולחים לגוגל:

python — image validation (PIL = ספריית עיבוד תמונה בפייתון) 
from PIL import Image     # PIL/Pillow: ספרייה לפתיחה ובדיקת קבצי תמונה
import requests           # להורדת התמונה מה-URL
from io import BytesIO   # לטעינת התמונה מהזיכרון (בלי לשמור לדיסק)

def validate_image(image_url: str) -> dict:
    issues = []

    # הורדת התמונה מה-URL
    response = requests.get(image_url, timeout=10)
    # פתיחה כאובייקט תמונה עם PIL
    img = Image.open(BytesIO(response.content))
    width, height = img.size  # קבלת מימדים בפיקסלים

    # בדיקה 1: מינימום גוגל (100x100)
    if width < 100 or height < 100:
        issues.append(f"קטנה מדי: {width}x{height} (מינימום: 100x100)")

    # בדיקה 2: מומלץ 800x800 לאיכות טובה
    if width < 800 or height < 800:
        issues.append(f"איכות נמוכה: {width}x{height} (מומלץ 800x800+)")

    # בדיקה 3: יחס תצוגה קיצוני (תמונה מאוד ארוכה/רחבה)
    ratio = width / height
    if ratio < 0.5 or ratio > 2.0:
        issues.append(f"יחס תצוגה לא תקין: {ratio:.2f} (מומלץ 1:1 עד 2:1)")

    return {"url": image_url, "valid": len(issues) == 0, "issues": issues}

# שימוש — סריקת כל הפיד:
for product in all_products:

    if not result["valid"]:
        print(f"בעיה ב-{product['id']}: {result['issues']}")

שגיאה 3: GTIN שגוי

איך עובד אימות GTIN?
GTIN-13 (ברקוד EAN) לא רנדומלי — הספרה האחרונה היא "check digit" שמחושבת מ-12 הספרות הקודמות. אלגוריתם: כפל ב-1 וב-3 לחלופין → סיכום → (10 - סכום % 10). אם הספרה ה-13 לא תואמת — ה-GTIN שגוי.
python — בדיקת תקינות EAN-13 
def validate_gtin(gtin: str) -> bool:
    """בדיקת תקינות GTIN-13 (ברקוד EAN) לפי האלגוריתם הרשמי"""
    # ווידוא שזה בדיוק 13 ספרות
    if not gtin or len(gtin) != 13 or not gtin.isdigit():
        return False

    # חישוב: כפל ב-1 (עמדות אי-זוגיות) וב-3 (עמדות זוגיות)
    total = sum(
        int(gtin[i]) * (1 if i % 2 == 0 else 3)
        for i in range(12)
    )
    # חישוב ספרת הביקורת הצפויה
    expected_check = (10 - (total % 10)) % 10
    # השוואה לספרה ה-13 בברקוד
    return expected_check == int(gtin[12])

validate_gtin("5901234123457")  # True  — ברקוד תקין
validate_gtin("1234567890123")  # False — ספרה 13 לא מסתדרת

מה ההבדל בין Disapproval Rate ל-Coverage Rate?
Disapproval Rate = מוצרים שגוגל דחתה — פורמט שגוי, מחיר לא תואם, תמונה לא תקינה. אלה מוצרים שכלל לא יופיעו.

Coverage Rate = מוצרים מאושרים שבפועל מקבלים impressions. אפשר שמוצר מאושר אבל לא מציג כי: תחרות גבוהה, מחיר גבוה מהשוק, ביקוש אפסי, או Bid נמוך מדי. Coverage נמוך = צריך לבדוק מחירים ואסטרטגיית בידינג.

Checklist פיד מנצח

  • שדות חובה מלאים ותקינים — id, title, price, image_link, availability
  • GTIN נכון לכל מוצר שיש לו ברקוד (EAN/UPC)
  • google_product_category מדויק עד הרמה הכי עמוקה בהיררכיה
  • item_group_id לכל קבוצת וריאנטים (צבע, מידה)
  • Custom Labels מחושבים אוטומטית לפי מרווח, ביצועים ומלאי
  • כותרות בנויות לפי [מותג + שם + מאפיינים קריטיים] — החשוב ראשון
  • תמונה ראשית 800×800+ רקע לבן + תמונות lifestyle נוספות
  • מחיר תואם 100% למחיר בדף המוצר (כולל מע"מ, כולל מבצעים)
  • עדכון לפחות כל שעה לזמינות ומחיר — אפס בזבוז תקציב על OOS
  • Supplemental Feed לשדות שהפיד הראשי לא מכסה
  • מוניטורינג אוטומטי — התראה כשהאחוז מאושרים יורד מתחת ל-90%
